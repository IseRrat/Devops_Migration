# 完成实验后的个人测试、报告、GitHub提交与归档

本页在每次E8/E9/E10完成后按需要执行。位置：学生自己的外层课程仓库根目录。不要在work/project内部提交学生报告。

## 1. 确认自己完成哪次实验

```bash
pwd
git branch --show-current
git config --local user.name
printf '本次OUT=%s\n' "$OUT"
ls "$OUT"
```

输入：当前会话。输出：个人student/学号/e8-e10分支、学号及本次目录。若OUT为空，按对应手册末尾恢复。阶段自动演示和手工分步的目录不同，应记录真正执行的一条路线，不把教师示例路径写成自己的。

## 2. 建立自己的报告、ADR和AI记录

先在本机材料中找到04_模板，服务器复制到本人专属目录：

```bash
SID=$(git config --local user.name)
MATERIALS="$HOME/devops-materials/DevOps_E8_E10"
REPORT_DIR="docs/students/$SID/e8-e10"
mkdir -p "$REPORT_DIR"
cp -n "$MATERIALS/04_模板/个人报告.md" "$REPORT_DIR/个人报告.md"
cp -n "$MATERIALS/04_模板/ADR.md" "$REPORT_DIR/ADR.md"
cp -n "$MATERIALS/04_模板/AI_USAGE.md" "$REPORT_DIR/AI_USAGE.md"
nano "$REPORT_DIR/个人报告.md"
```

输入：报告模板与本人实际实验结果。输出：docs/students/学号/e8-e10下三份文档，cp -n保留已填写文件。nano保存为Ctrl+O、Enter，退出为Ctrl+X。

报告逐项填写：本组GitHub URL、学生源码SHA（OUT/student-source-commit.txt）、镜像ID、本次命令、OUT、预期和实际结果、修改函数及新增测试。样例内部提交是被测项目版本，不替代学生源码SHA。

A E8记录真实BuildChecker来源与精确MD/RD；A E9填写C0—C3变化、复用/刷新和新增/消除；A E10填写30行对照以及每类中位数和离散情况。

B E8记录报告版本、Patch与旧报告拒绝；B E9说明三种风格修改位置；B E10填写三次接受/拒绝、各check、原字节保持和动态重检。ADR说明选择及代价；AI_USAGE如实记录模型使用、人工修改与验证；未调用则写未调用。

## 3. 修改参考代码并增加自己的独立测试

```bash
grep -n '^def ' labs/e8e10/lab.py
nano labs/e8e10/test_profile.py
```

输入：各实验末尾的自主任务。输出：新增测试或实现。[个人测试编写示例](08_个人测试编写示例.md)给出六个完整测试类及粘贴位置，先选择本实验、本轨道的一例，再加入自己的输入变化。每个测试先写独立预期，例如“添加extra.h包含后，main.o应新增MISSING extra.h”，再运行代码验证。不要只把实现计算值复制成预期。

需要在lab.py修改实现时用nano编辑对应函数；先查看git diff确认只改了目标逻辑。输入超出受限Make配置时，先明确支持或拒绝规则，再补用例。

## 4. 执行定向测试并保存真实日志

```bash
SID=$(git config --local user.name)
TEST_LOG="work/unit-tests-$(date +%Y%m%d-%H%M%S).log"
docker run --rm --network none --user "$(id -u):$(id -g)" \
  -e HOME=/tmp -v "$PWD:/course" -w /course "course-e8e10:$SID" \
  python3 -m unittest discover -s labs/e8e10 -p test_profile.py -v \
  > "$TEST_LOG" 2>&1
TEST_CODE=$?
cat "$TEST_LOG"
printf 'TEST_EXIT_CODE=%s\n' "$TEST_CODE"
```

输出：原包7项通过；新增自己的测试后数量增加，最终为OK、退出0。失败时根据测试名和断言改受影响代码，再重跑该测试；不因一处报告文案修改重复构建镜像。核心逻辑修改后，用新OUT重跑对应轨道/阶段，保存修改前后结果。

## 5. 检查改动并生成个人提交

```bash
git status --short
git diff --stat
git diff -- labs/e8e10/lab.py labs/e8e10/test_profile.py
```

输入：本人修改与报告。输出：清楚的diff。确认没有真实凭据、临时输出和他人实现后，按自己实际改动选择暂存文件。下面示例为测试、实现和本人报告：

```bash
git add labs/e8e10/lab.py labs/e8e10/test_profile.py "docs/students/$SID/e8-e10"
git diff --cached --check
git diff --cached --stat
git commit -m "E8-E10: add student $SID experiment and verification"
git rev-parse HEAD
```

通过条件：提交成功，保存完整学生commit。未修改源码时只提交真实填写的报告；不要制造空提交。work默认忽略，在下面归档步骤保存。

## 6. 推送本人分支并创建PR

```bash
E8_PACK="$HOME/devops-materials/DevOps_E8_E10/03_实验包"
SID=$(git config --local user.name)
source "$E8_PACK/github_session.sh"
BRANCH=$(git branch --show-current)
GH_REPO=$(gh repo view "$(git remote get-url origin)" --json nameWithOwner --jq .nameWithOwner)
printf 'GitHub=%s\n当前分支=%s\n' "$GH_REPO" "$BRANCH"
```

通过条件：同一本组仓库，BRANCH为本人student/学号/e8-e10。若在main，先回正确个人分支，不直接push main。

```bash
git push -u origin "$BRANCH"
gh pr list --repo "$GH_REPO" --state open --head "$BRANCH"
```

若已有自己的Open PR，继续更新它，不重复创建。没有时：

```bash
gh pr create --repo "$GH_REPO" --base main --head "$BRANCH" \
  --title "E8-E10 student contribution $SID" \
  --body-file "docs/students/$SID/e8-e10/个人报告.md"
```

输出：真实PR链接。浏览器打开该链接，在Files changed核对只有自己的预期修改。Changes requested时按反馈推送同一分支，PR自动更新。[GitHub CLI创建PR说明](https://cli.github.com/manual/gh_pr_create)支持通过--body-file保留报告原始换行。

## 7. 等待Actions并绑定真实提交

```bash
SOURCE_SHA=$(git rev-parse HEAD)
gh run list --repo "$GH_REPO" --workflow e8e10.yml --branch "$BRANCH" \
  --commit "$SOURCE_SHA" --json databaseId,headSha,status,conclusion,url --limit 10
```

输出：本次SHA的运行。push和pull_request可能各触发一个运行，验收PR时优先检查pull_request对应记录。刚push列表可能暂时为空，稍后再查，不反复提交新commit。

选择运行ID后：

```bash
read -r -p '本次SHA对应的运行ID: ' RUN_ID
gh run watch "$RUN_ID" --repo "$GH_REPO" --exit-status
CI_CODE=$?
printf 'CI_EXIT_CODE=%s\n' "$CI_CODE"
gh run view "$RUN_ID" --repo "$GH_REPO" --json headSha,conclusion,url
```

通过条件：headSha等于SOURCE_SHA，conclusion=success。gh run watch的退出码按实际记录；失败时执行下段查看日志，而非忽略退出码。[GitHub CLI运行等待说明](https://cli.github.com/manual/gh_run_watch)。

```bash
gh run view "$RUN_ID" --repo "$GH_REPO" --log-failed
```

下载成功或失败的真实证据，保存代码版本和运行信息：

```bash
CI_OUT="work/ci-e8e10/$RUN_ID"
mkdir -p "$CI_OUT"
gh run view "$RUN_ID" --repo "$GH_REPO" --json headSha,conclusion,url > "$CI_OUT/run.json"
gh run download "$RUN_ID" --repo "$GH_REPO" --dir "$CI_OUT/artifacts"
cat "$CI_OUT/run.json"
ls "$CI_OUT/artifacts"
```

输出：本次run.json与artifact目录。artifact保留14天，及时下载；早期构建失败时可能没有完整实验产物，保留失败日志与原因。

## 8. 组长检查和合并，学生同步

组长在PR核对个人贡献、报告、原E7检查以及e8e10-quality-gate。通过后Merge，记录合并SHA。新增检查是否加入main必需项由教师/组长按E7流程设置，并保留原有必需检查；本文不替换原规则数组。

学生需要继续在个人分支开发时，工作区先干净，再：

```bash
git switch main
git pull --ff-only origin main
git switch "student/$SID/e8-e10"
git merge --no-edit main
```

输出：本地main和个人分支都获得组长新合并内容。普通merge冲突逐文件处理；不能用reset --hard清掉个人工作。已合并分支后若没有新改动，不重复创建同一PR。

## 9. 打包服务器证据并下载到电脑

先确认docs中已写入真实OUT与代码SHA，work中包含本人的实验和Actions证据。当前目录为外层个人仓库：

```bash
SID=$(git config --local user.name)
SUBMIT_DIR="$HOME/devops-submissions/$SID"
mkdir -p "$SUBMIT_DIR"
ARCHIVE="$SUBMIT_DIR/E8-E10-$(date +%Y%m%d-%H%M%S).tar.gz"
tar --exclude='.git' --exclude='.env' --exclude='__pycache__' \
  --exclude='*.pem' --exclude='*.key' \
  -czf "$ARCHIVE" labs/e8e10 run_lab.py "docs/students/$SID/e8-e10" work
printf '归档=%s\n' "$ARCHIVE"
ls -lh "$ARCHIVE"
tar -tzf "$ARCHIVE" | head -n 30
```

输入：本人源码、报告和原始证据。输出：仓库外tar.gz，目录包含上述四类材料。归档默认不带内部.git，因此需要保留本人的GitHub提交和JSON中的样例SHA；样例可通过文件与步骤重新建立。若教师要求内部完整Git历史，应单独归档相应project/.git并按提交要求处理。

电脑SFTP下载打印的完整路径；或电脑执行scp，中文替换为真实值：

```text
scp 登录账号@本组公网IP:服务器打印的归档完整路径 本地保存目录
```

电脑解压抽查：本人报告、E8基线或Patch、E9变化或风格计划、E10矩阵/验证、steps日志、Actions artifact。服务器和电脑各保留一份。

## 10. 排错时先定位哪一层失败

|现象|看什么|处理后怎样继续|
|---|---|---|
|cd或source失败|pwd、真实目录、包版本|修正路径；先确认helper存在|
|main有文件但个人分支没有|git branch --show-current|在个人分支合入最新main|
|pull会覆盖本地文件|git status --short|先commit或stash；git add不能解决未保存问题|
|lab_ready缺镜像|docker image inspect|执行run_lab.py build，成功再进入实验|
|输出目录已存在|OUT和目录内容|新建OUT，旧证据不覆盖|
|ModuleNotFoundError|是否使用lab_python|source新版helper；它设置PYTHONPATH和既有环境|
|strace权限错误|steps日志中的系统错误|确认SYS_PTRACE和云端容器策略|
|编译失败|命令、gcc输出、输入文件|修正输入或明确失败用例；新OUT重做|
|STALE_REPORT|报告commit和project HEAD|重新采集对应提交，不能直接改报告SHA绕过检查|
|增量结果不一致|actual/declared/findings具体边|核对include/配置失效；只重跑受影响用例|
|B测试拒绝被当作失败|validation.accepted/checks/rollback|预期拒绝且源字节不变时，该场景通过|
|GitHub认证或权限失败|显示账号、origin、邀请|恢复本人认证并确认Write权限|
|CI还是旧提交|PR head与run.headSha|等最新SHA运行，选择相应RUN_ID|
|SSH断线|work/last-阶段-轨道.path与steps最后日志|恢复OUT；仅继续未完成步骤|

提交问题时提供：实际命令、pwd、当前分支、OUT、步骤日志最后30行、状态JSON。明确故障在材料/身份/构建/算法/验证/CI哪一层，便于教师定位。
