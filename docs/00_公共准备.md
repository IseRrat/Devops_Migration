# 公共准备：从登录到能开始E8的完整操作

## 先看分工和执行位置

|操作者|只做一次的事|每次要做的事|
|---|---|---|
|教师/组长|确认本组GitHub仓库；导入E8—E10代码；PR合并main|检查教学材料、演示环境和服务器容量|
|每名学生|自己的仓库克隆、身份、个人分支、环境镜像|SSH、进入自己目录、恢复认证、设置OUT|

电脑终端负责SSH；浏览器负责GitHub认证、PR和Actions；Linux服务器终端负责Git、Python入口和Docker。`lab_python`自动进入Docker容器，运行结束后回到服务器终端。不要把源码修改、仓库操作放到一个临时容器的手工shell里。

每个代码框完整复制，在预期输出符合后进入下一框；`root@服务器:目录#`等提示符不用复制。下方出现`read`时，在提示后填写本人真实值。A的原仓库目录通常为buildchecker，B为draft；学号是本人数字学号。

## 1. 从电脑登录本组服务器

**目的**：进入有Docker的Linux环境。**输入**：教师提供的服务器账号/IP/登录凭据。

电脑Mac终端或Windows PowerShell执行，中文词替换为真实值：

```text
ssh 登录账号@本组公网IP
```

例如账号为root时，用户名为root；使用密钥则加`-i 私钥文件路径`。首次连接按课程要求核对主机指纹后输入yes，输入密码时不显示字符，按Enter提交。

登录后在服务器运行：

```bash
hostname
uname -s
pwd
id
```

**输出/通过条件**：uname显示Linux，pwd显示服务器目录。若仍在电脑目录、uname显示Darwin，说明SSH未登录成功；先重新连接。

## 2. 上传最新材料，并保留旧材料备份

**目的**：本次详细手册新增classroom_helpers.sh，必须使用新版分发包。**输入**：下载到电脑的DevOps_E8_E10_20261031.zip。

电脑用FinalShell/WinSCP/SFTP连接同一IP和账号，进入服务器HOME，把ZIP上传到这里。也可在电脑使用scp，中文路径替换为真实本地ZIP路径：

```text
scp 本地ZIP完整路径 登录账号@本组公网IP:~/
```

服务器执行：

```bash
ls -lh "$HOME/DevOps_E8_E10_20261031.zip"
command -v unzip
```

**输出/通过条件**：ZIP大小大于0，unzip有可执行路径。找不到ZIP时回到SFTP核对上传位置；没有unzip时由服务器管理员安装，不在每个学生目录重复安装。

已有旧版材料时，下面先将其改名备份，再解压新版，避免`unzip -n`留下旧同名文件：

```bash
mkdir -p "$HOME/devops-materials"
if [ -d "$HOME/devops-materials/DevOps_E8_E10" ]; then
  OLD_MATERIALS="$HOME/devops-materials/DevOps_E8_E10-backup-$(date +%Y%m%d-%H%M%S)"
  mv "$HOME/devops-materials/DevOps_E8_E10" "$OLD_MATERIALS"
  printf '旧材料已保留在 %s\n' "$OLD_MATERIALS"
fi
unzip -n "$HOME/DevOps_E8_E10_20261031.zip" -d "$HOME/devops-materials"
E8_PACK="$HOME/devops-materials/DevOps_E8_E10/03_实验包"
ls "$E8_PACK/run_lab.py" "$E8_PACK/classroom_helpers.sh" "$E8_PACK/github_session.sh"
```

**输出**：完整DevOps_E8_E10材料目录，三个文件可见。此操作只更新分发材料目录，学生仓库和work不在此目录，保留原样。

## 3. 检查环境，一组先由教师核对

```bash
git --version
python3 --version
docker version
docker compose version
gh --version
df -h .
free -h
```

**输入**：现有E4—E7服务器。**输出/通过条件**：Python至少3.9（入口使用Path.is_relative_to），Docker同时显示Client/Server，GitHub CLI可用。推荐沿用前期至少4GiB可见内存、40GiB可用磁盘的安排。缺工具时按E4—E7环境手册由管理员统一处理。多人首次构建由组长安排串行，不并发下载。

## 4. 进入本人的原课程仓库

**输入**：本人学号、轨道。**操作**：

```bash
read -r -p '本人学号: ' SID
read -r -p '轨道A或B: ' TRACK
case "$TRACK" in
  A) REPO_NAME=buildchecker ;;
  B) REPO_NAME=draft ;;
  *) echo '请输入大写A或B，再重做本步' ;;
esac
cd "$HOME/devops-students/$SID/$REPO_NAME"
pwd
git rev-parse --show-toplevel
git remote -v
git config --local user.name
```

**通过条件**：pwd与Git根目录相同，origin为本组https://github.com/...地址，user.name为本人数字学号。若目录名与上方示例不同，cd到自己的实际仓库。cd失败后不要继续执行后续Git操作。

若从未克隆过本组仓库：先在服务器HOME设置学号，source材料中的github_session.sh完成本人浏览器授权，再使用下面的首次克隆路线。已有克隆直接跳到第5步。

```bash
E8_PACK="$HOME/devops-materials/DevOps_E8_E10/03_实验包"
source "$E8_PACK/github_session.sh"
read -r -p '本组GitHub HTTPS克隆地址: ' GROUP_REPO
read -r -p '本人已验证邮箱或GitHub隐私邮箱: ' STUDENT_MAIL
mkdir -p "$HOME/devops-students/$SID"
cd "$HOME/devops-students/$SID"
git -c credential.helper= -c 'credential.helper=!gh auth git-credential' \
  clone --branch main "$GROUP_REPO" "$REPO_NAME"
cd "$REPO_NAME"
git config --local user.name "$SID"
git config --local user.email "$STUDENT_MAIL"
source "$E8_PACK/github_session.sh"
```

输出：origin指向同一本组仓库，当前main。空仓库提示说明组长还没初始化，先由组长完成原课程建仓。

## 5. 恢复本人GitHub认证，处理未提交修改

```bash
E8_PACK="$HOME/devops-materials/DevOps_E8_E10/03_实验包"
SID=$(git config --local user.name)
source "$E8_PACK/github_session.sh"
git status --short
```

**目的**：当前会话使用本人GH_CONFIG_DIR，仓库局部helper指向本人认证。**预期**：显示GitHub account:本人的账号，status为空。首次授权会显示device code，在电脑浏览器打开https://github.com/login/device完成认证；不要把验证码写入代码或报告。

若status有输出：先查看修改；需要保留又暂不提交时用：

```bash
git stash push -u -m "save personal work before E8-E10 sync"
git stash list
git status --short
```

**输出**：修改保存为stash，status为空。work被忽略，继续留在原路径。同步后按实际需要恢复个人实现；不要直接恢复旧Dockerfile覆盖组长统一环境。若存在冲突状态，先按提交与排错手册处理，不继续import或pull。

## 6. 组长导入代码：每组一次，其他学生先等待

**目的**：在同一GitHub仓库中加入独立labs/e8e10和新workflow。先更新main并判断是否已经导入：

```bash
git switch main
git pull --ff-only origin main
git ls-tree --name-only HEAD labs/e8e10/lab.py run_lab.py .github/workflows/e8e10.yml
```

若三个路径都出现，说明已导入，跳到第8步；新版classroom_helpers.sh直接从材料目录source即可，不必重复提交参考代码。

若尚未导入，确认status干净后执行：

```bash
git switch -c teaching/e8-e10
mkdir -p labs/e8e10 .github/workflows
cp -R "$E8_PACK/labs/e8e10/." labs/e8e10/
cp "$E8_PACK/run_lab.py" ./run_lab.py
cp "$E8_PACK/.github/workflows/e8e10.yml" .github/workflows/e8e10.yml
git check-ignore work/
git add labs/e8e10 run_lab.py .github/workflows/e8e10.yml
git diff --cached --check
git diff --cached --stat
```

**输入**：干净main和本包模板。**输出**：暂存新增实验代码和workflow；git diff --cached --check成功时无输出。复制采用源目录末尾/.，防止已有目录时产生e8e10/e8e10嵌套。

若提示分支already exists，不使用强制重建；切换到该分支，检查是否已有上次未完成导入。原仓库已有学生实现时先比较同名文件，不覆盖个人实现。确认暂存只有本次课程代码后提交：

```bash
git commit -m 'E8-E10: add incremental checking and repair teaching labs'
git push -u origin teaching/e8-e10
git rev-parse HEAD
```

**输出**：分支上传成功和完整SHA。push认证失败时回第5步；权限失败时确认本人已接受组长的Write邀请。

## 7. 组长创建PR、等待检查并合并

浏览器进入本组GitHub：Pull requests → New pull request，base选择main，compare选择teaching/e8-e10，检查Files changed，填写标题并Create pull request。等待Checks中原E7检查及e8e10-quality-gate成功，再点击Merge pull request → Confirm merge。

**输入**：刚上传的导入分支。**输出/通过条件**：PR状态为Merged。只创建PR还没有更新main，不能让组员提前pull。

失败时进入失败job查看第一处错误：下载错误处理镜像源/网络，断言错误查对应报告。修复推送同一分支，等最新SHA检查通过。真实运行由课堂账号产生，本地材料里的示例运行ID不填到这里。

组长合并后执行：

```bash
git switch main
git pull --ff-only origin main
git rev-parse HEAD
ls run_lab.py labs/e8e10/lab.py .github/workflows/e8e10.yml
```

将仓库地址、main的新SHA和“导入PR已合并”告知组员。

## 8. 每位学生同步main并建立/更新个人分支

在本人仓库根目录复制执行；已有分支会合入main，首次则从最新main创建：

```bash
(
set -e
test -z "$(git status --porcelain)" || { echo '先保存未提交修改'; exit 1; }
E8_PACK="$HOME/devops-materials/DevOps_E8_E10/03_实验包"
SID=$(git config --local user.name)
source "$E8_PACK/github_session.sh"
git switch main
git pull --ff-only origin main
BRANCH="student/$SID/e8-e10"
if git show-ref --verify --quiet "refs/heads/$BRANCH"; then
  git switch "$BRANCH"
  git merge --no-edit main
else
  git switch -c "$BRANCH" main
fi
ls run_lab.py labs/e8e10/lab.py labs/e8e10/test_profile.py
)
```

**输出/通过条件**：进入student/学号/e8-e10，三个文件存在。若main有文件、个人分支没有，说明尚未合入main；本段已包含该步骤。合并冲突时停在冲突位置，保留个人改动逐文件处理后再继续。

## 9. 构建个人环境镜像，并保存构建日志

```bash
mkdir -p work
ENV_LOG="work/environment-build-$(date +%Y%m%d-%H%M%S).log"
python3 run_lab.py build > "$ENV_LOG" 2>&1
ENV_CODE=$?
tail -n 35 "$ENV_LOG"
printf 'ENV_BUILD_EXIT=%s\n日志=%s\n' "$ENV_CODE" "$ENV_LOG"
```

**输入**：environment中的Dockerfile、锁文件和BuildChecker源码。**作用**：docker build建立含gcc、make、git、strace及Python依赖的实验环境。首次下载可能耗时，当前终端等待完成；可另开SSH终端tail -f这个日志查看进度。

**通过条件**：ENV_BUILD_EXIT=0；日志中无最终ERROR。随后：

```bash
SID=$(git config --local user.name)
docker image inspect "course-e8e10:$SID" --format '{{.Id}}'
docker run --rm --network none "course-e8e10:$SID" gcc --version
docker run --rm --network none "course-e8e10:$SID" make --version
```

输出：镜像ID、gcc与GNU Make版本。已有同一环境镜像且环境代码未变时跳过重复build，直接检查镜像。lab.py通过挂载运行，修改它不需要重新构建未变的环境。

## 10. 验证课堂辅助命令可用

```bash
E8_PACK="$HOME/devops-materials/DevOps_E8_E10/03_实验包"
source "$E8_PACK/classroom_helpers.sh"
lab_ready
```

**输出**：本人仓库、学号、course-e8e10:学号。没有错误后进入本轨道手册：A组先E8 A，B组先E8 B。lab_python自动添加容器工作目录、镜像、禁网、SYS_PTRACE与PYTHONPATH；它只简化课堂长命令，没有修改检测或补丁算法。

课堂读命令时按下表解释：

|写法|输入/作用|输出|
|---|---|---|
|source classroom_helpers.sh|把材料中的函数加载到当前SSH会话|新增lab_ready、lab_new_run、lab_python三个命令|
|lab_ready|读取当前Git根目录和user.name，确认个人镜像存在|LAB_REPO_ROOT、SID、LAB_IMAGE|
|lab_new_run e8 A|阶段与轨道，创建不重复的目录|OUT和work/last-e8-A.path|
|lab_python "$OUT" <<'PY'|把PY标记之间的Python源码送入既有容器；OUT作为第一个参数|终端结果、steps日志和STEP_EXIT_CODE|
|Path(sys.argv[1])|读取上一行传入的OUT，当前容器目录是/course|Python中的输出目录对象|
|--network none|容器运行阶段使用已安装工具和本地样例|实验采集不依赖外部下载|
|--cap-add SYS_PTRACE|允许BuildChecker调用strace跟踪构建|trace/t.*原始系统调用记录|
|-v 仓库:/course 与 -w /course|挂载本人仓库并指定容器工作目录|容器文件会保存到本人work|
|assert 条件|把本步独立预期写成可执行判定|满足则继续；不满足产生AssertionError|
|cat / grep / ls|读取文件、定位内容和列目录|终端显示，不修改实验输入|

`<<'PY'`和单独一行的`PY`组成完整输入块，结束标记必须顶格；不要遗漏最后一行。命令中的`$OUT`由服务器shell展开，Python里的`out/'project'`再拼接文件路径。`STEP_EXIT_CODE=0`对应这一代码块成功；程序有意拒绝某个候选时，仍需由assert核对拒绝原因和源文件状态。

## 11. 变量、路径与断线恢复速查

|名称|含义|何时恢复|
|---|---|---|
|SID|本人数字学号|新SSH会话从本仓库Git配置读取|
|E8_PACK|解压材料中的03_实验包|新SSH重新赋值|
|OUT|本次实际证据目录|读取work/last-阶段-轨道.path|
|LAB_IMAGE|个人实验镜像|source辅助脚本后lab_ready设置|
|GH_CONFIG_DIR|本人GitHub认证目录|source github_session.sh恢复|

每次运行lab_new_run会建立新OUT，不会恢复旧OUT。只恢复旧实验时按各实验末尾命令读取last路径，再确认最后一步日志。不要把电脑的HOME路径、服务器HOME和容器/course混用：宿主机当前仓库通过挂载对应容器/course。
