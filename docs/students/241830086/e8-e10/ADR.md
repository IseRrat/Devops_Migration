# 重复的缺失依赖只修复一次

固定报告可能包含重复的缺失依赖。原 `patch()` 逐行生成修改，导致同一个先决条件与同一条修改计划被追加两次。

在处理 MISSING 时按目标与依赖组成的二元组去重，保留首条记录及输入顺序。按依赖名全局去重会漏掉其他目标上同名的缺失依赖。只在最终 diff 清理重复文本会让计划继续含有重复项，也更容易破坏 Makefile 风格。

这项决策仅去除重复报告项。变量定义被多个目标共享时，修改其定义仍会影响其他引用者，需要另外分析。候选生成和质量判定继续沿用课程流程：先在副本应用和验证，通过后写回 Makefile；拒绝时比较原文件字节。

同一缺失项重复输入在 direct、macro、mixed 中的修改次数由两次变为一次。两轮原有单元测试均通过，E10 两个拒绝场景的字节比较均为 0。原始证据索引见个人报告。
