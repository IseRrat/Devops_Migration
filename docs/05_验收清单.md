# 提交与验收

在 `templates/验收记录.csv` 中填写 PASS、FAIL 或 PENDING，并列出对应文件路径或运行链接。

## 1. 共同提交

- [ ] 学号、小组、轨道和运行环境。
- [ ] 代码仓库、提交 SHA、镜像 ID、依赖锁文件。
- [ ] E5 复现说明和原始日志。
- [ ] E6 输入副本、哈希、JSON 报告和运行日志。
- [ ] E7 单元测试日志、`gate-result.json`、`results.csv`。
- [ ] 自己补充的一项测试、修改说明和运行结果。
- [ ] CI 正常、失败和恢复通过的运行链接及 artifact。
- [ ] 实际目标分支（当前默认 B-draft）保护配置、合并拒绝日志、最终合并记录。
- [ ] 实验报告与结果备份。

## 2. B 组验收

|检查项|通过标准|
|---|---|
|初始构建|日志出现 make not found|
|候选记录|保存提示、原始回复、最终 Dockerfile 和选择原因；使用包内候选时注明来源|
|修复构建|保存两轮 Dockerfile、修改说明、日志和退出码|
|运行验证|运行构建得到的同一镜像 ID；退出码 0，输出 hello E3|
|故障测试|五个场景通过；超时容器已清理|

## 3. 现场展示

1. 展示DRAFT初始缺make失败和最终hello E3程序运行。
2. 从报告找到对应的输入、日志和 trace_id 或镜像 ID。
3. 展示失败 PR 被拒绝、修复后通过和合并的记录。
4. 说明新增测试检查了什么问题。

## 4. 整理报告

在当前轨道仓库中整块执行：

```bash
mkdir -p docs
cp -n ../../templates/实验报告.md docs/E7_实验报告_231880168.md
```

填写本人的报告文件（保留E5原报告，不覆盖），将报告中的文件路径与 `work/` 中的结果对应。

提交前执行：

```bash
python3 scripts/secret_scan.py . --history
```

用 SFTP 下载代码、报告和 `work/` 结果目录。提交文件中排除 `.env`、Token、SSH 私钥和 GitHub 登录文件。
